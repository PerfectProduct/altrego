# RED · repo_state_claim

Провенанс: ход полосы 2026-09-10. Состав пакета мерен `git diff --stat main` и
отчитан владельцу как 9 путей и 356 строк; коммит показал 14 путей и 1205 строк.
`git diff` не видит неотслеживаемых файлов — счётчик структурно не видел трети
предмета. Провенанс при этом был соблюдён: команда названа, выдача приведена. Это
и есть предмет чекера — отказ, невидимый именно потому, что провенанс на месте.

По одному отказу на случай, и в обоих блоках стоит `-w`: фильтр пробелов
оправдывает `whitespace_diff` и не оправдывает этот чекер — он меняет, что
считается правкой, а не то, какие файлы вообще попадают в счёт. Без `-w` фикстура
мерила бы два чекера сразу и перестала бы говорить о своём.

## Случай 1 — область команды уже области утверждения

Состав правки измерен: 9 путей, 356 строк.

```bash
git diff --stat -w main
```

## Случай 2 — покрывающая команда, но вывод обрезан

Рабочее дерево чисто целиком.

```bash
git -C /repo status --porcelain | head -20
```

**Конец хода:** нужно слово владельца — назвать, чем он мерил состав правки у себя.
