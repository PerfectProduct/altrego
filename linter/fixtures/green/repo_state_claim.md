# GREEN · repo_state_claim

Тот же предмет: область команды покрывает область утверждения. **По одному
оправданию на случай** — сложи два в один блок, и мёртвое оправдание станет
неотличимо от живого: калибровка печатает ноль в обоих случаях. Оправдания здесь
разные по механизму, и каждое проверяется своей мутацией.

## Случай 1 — покрывающая команда перебивает узкую

Состав правки — 14 путей, 1205 строк.

```bash
git diff --stat -w main
git status --porcelain
```

## Случай 2 — предел назван словами

Состав правки по отслеживаемым файлам — 9 путей, без учёта неотслеживаемых.

```bash
git diff --stat -w main
```

## Случай 3 — предмет утверждения и есть дифф

В diff 4 файла — выдача `git diff --stat -w`, строка «4 files changed». Область
команды здесь равна области утверждения, и сужать нечего.

## Случай 4 — труба, но не усечение

Незакоммиченных файлов нет: счётчик считает весь вывод, а не его голову.

```bash
git -C /repo status --porcelain | wc -l
```

## Случай 5 — узости нет в самой команде

Состав правки — 14 путей, 1205 строк.

```bash
git diff --cached --stat -w
```

**Конец хода:** нужно слово владельца — подтвердить состав правки по своей консоли либо назвать расхождение.
